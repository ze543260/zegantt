Alto impacto

A sidebar esquerda (lista de tarefas) tem largura fixa de LEFT_W = 460px definida em constants.ts. Usuários com nomes de tarefa longos precisam de mais espaço; usuários com datasets simples preferem menos.

  • Adicionar um divider arrastável entre GanttGrid e GanttChart
  • Salvar preferência no localStorage
  • Expor prop sidebarWidth para controle externo
  • Limites mínimo (200px) e máximo (700px) para evitar layout quebrado

Alto impacto

O sistema de temas já usa 100% CSS variables (--zg-surface, --zg-header-bg, etc.) mas não há paleta escura definida. Implementar dark mode é apenas adicionar um segundo conjunto de valores para as variáveis.

  • Adicionar preset darkTheme exportado da lib
  • Suporte a data-theme="dark" no wrapper
  • Respeitar prefers-color-scheme: dark automaticamente quando theme="auto"
  • Prop theme="dark" | "light" | "auto" no ProjectGantt

Setas de Dependência por Tipo
Médio

Todas as setas usam a mesma cor C.arrow (#7B7B7B). Em projetos com muitas dependências mistas (FS, SS, FF, SF), é difícil distinguir a relação sem clicar na tarefa.

  • FS (Finish→Start) — verde escuro (padrão, mais comum)
  • SS (Start→Start) — laranja
  • FF (Finish→Finish) — roxo
  • SF (Start→Finish) — azul
  • Legenda pequena no header ou tooltip ao passar em cima

Os grupos ("Steps", "Milestones") exibem apenas um badge com contagem. Adicionar a média ponderada de progresso das tarefas do grupo dá uma visão rápida sem precisar expandir.

Lag Visível nas Setas de Dependência
Médio

O lag (atraso em dias entre tarefas dependentes) só é visível ao clicar na tarefa e abrir o popup de relações. Em projetos com muitas dependências com lag, o usuário não sabe visualmente que há uma folga.

  • Renderizar label "+Xd" ou "-Xd" no meio da seta SVG
  • Apenas quando lag ≠ 0
  • Fundo branco/surface para legibilidade sobre o grid
  • Tamanho pequeno para não poluir o gráfico

A prop loading={true} existe no ProjectGanttProps mas nenhuma UI de skeleton foi encontrada no codebase. Ao carregar dados, o usuário vê uma tela em branco.

  • Skeleton animado para sidebar (linhas de nome/data)

  • Animação shimmer com CSS

Botão "Ir para Hoje"
Alto impacto

Quando o dataset cobre meses ou anos, o marcador de "hoje" pode estar fora da viewport. Não há como voltar para ele sem scrollar manualmente. Botão simples no header resolve isso.

  • Botão no header ao lado dos controles de view mode
  • Animação de scroll suave (scrollIntoView com behavior: "smooth")
  • Aparece apenas quando "hoje" está fora da viewport atual
  • Texto: "Hoje" com ícone de calendar ou target

Barra de Busca / Filtro por Texto
Alto impacto

Atualmente o único filtro disponível é por tipo (Steps/Milestones/Events/Notes). Em projetos com 50+ tarefas, encontrar uma específica requer scroll manual. Uma busca por nome resolve isso.

  • Input de busca no header com debounce (300ms)
  • Filtra por nome em todos os tipos visíveis
  • Destaca o texto encontrado na sidebar
  • Mantém agrupamento, apenas esconde não-matches
  • Ativado por Ctrl+F ou Cmd+F
  • Badge no botão mostrando total de resultados

View Mode "Semana"
Alto impacto

Atualmente existem dois zoom levels: Day (cada coluna = 1 dia, span mensal) e Month (cada coluna = 1 mês, span anual). Falta um nível intermediário: Semana (cada coluna = 1 dia, span de ~3 meses com mais espaço por dia).

  • Segmented control: Semana | Mês | Ano
  • Header superior: mês/ano
  • Header inferior: dias agrupados por semana
  • Mais espaço por dia que o day mode atual
  • Ideal para planejamento de sprints (2–3 semanas)

Undo / Redo de Operações de Drag
Alto impacto

Ao arrastar ou redimensionar uma tarefa, a mudança é chamada imediatamente em onTaskChange. Não há como desfazer. Um usuário que arrastou acidentalmente precisa ir ao backend para corrigir.

  • Stack de histórico local com até 20 operações
  • Undo com Ctrl+Z / Redo com Ctrl+Shift+Z
  • Botões de undo/redo discretos no header
  • onTaskChange chamado apenas no redo/finalização
  • Stack limpo ao receber novos dados via props

Seleção Múltipla de Tarefas
Alto impacto

Atualmente apenas uma tarefa pode ser selecionada por vez (selectedTaskId: string | null). Para mover um conjunto de tarefas ou aplicar uma ação em lote, o usuário precisa repetir a operação manualmente para cada uma.

  • Ctrl+Click para adicionar à seleção
  • Shift+Click para selecionar range
  • Barra de ações em lote aparece quando há 2+ selecionadas
  • Ações: mover em bloco, deletar em lote, atualizar progresso
  • Callback onBulkChange(tasks[])

Export para Imagem / PDF
Alto impacto

Gerentes de projeto precisam incluir o Gantt em apresentações e relatórios. Atualmente o único jeito é um print screen manual. Uma exportação nativa seria muito valorizada.

  • Export PNG via html-to-image ou dom-to-image
  • Export PDF via jsPDF + captura de canvas
  • Opção de exportar apenas o range visível ou o projeto inteiro
  • Esconde controles de UI na captura (botões, popups)
  • Callbacks: onExportStart / onExportEnd

Edição Inline de Progresso
Alto impacto

O progresso (conclusionPercent) é apenas lido da prop e exibido. Para atualizar, o usuário precisa usar o sistema externo. Um slider inline no popup de ação tornaria o Gantt muito mais interativo.

  • Slider ou input numérico no popup de tarefa existente
  • Preview em tempo real na barra enquanto arrasta
  • Callback onProgressChange(taskId, percent)
  • Confirmação com Enter ou blur do input
  • Cancela com Escape

Feriados e Dias Não-Úteis Customizáveis
Médio

Atualmente apenas finais de semana têm fundo diferenciado (isWeekend no grid SVG). Projetos de construção frequentemente têm feriados nacionais, paradas programadas, e períodos de obra suspensa que precisam ser sinalizados.

  • Prop holidays: Date[] ou nonWorkingDays: Date[]
  • Renderizar fundo vermelho claro nesses dias (como weekends, mas distinto)
  • Tooltip ao passar sobre o dia com o motivo (se fornecido)
  • Integra com cálculo de critical path (ignora dias não-úteis)
